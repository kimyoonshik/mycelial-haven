# Mycerra 쇼핑몰 주문·인보이스·결제·발송 공정 (SOP)

> 대상: 세이브어스(주) 영업·생산·재무 담당자
> 기준 설정: 운영 도구(`npm run cms`) → 크기·가격 탭 (`src/content/data/commerce.json`: 단가·크기·최소/최대 물량·배송비·판매자 정보)
> 최종 갱신: 2026-10-31

---

## 1. 주문 경로 한눈에 보기

| 구분 | 조건 | 결제 방식 | 고객 화면 |
|------|------|----------|----------|
| **A. 개인 주문** | 정규원단 합계 **20–100 sqft**, 또는 **샘플만**(최대 10장), 해외 구매자 | PayPal 즉시 결제 (PayPal 계정 또는 카드) | 장바구니 → `/shop/checkout` |
| **B. 발주 주문** | 정규원단 **100 sqft 초과**, 샘플 10장 초과, 또는 기업 거래 조건 요청 | 승인 인보이스 → PayPal 인보이스 또는 T/T 송금 | 장바구니 → `/shop/po` 발주희망서 |
| **C. 국내 주문** | 구매자 국가 = 대한민국 (물량 무관) | 견적서·세금계산서 → 원화 계좌이체 | 결제 화면에서 자동으로 `/shop/po?domestic=1` |

- 판매 단위: **원단 장(piece)** — 4개 가공 조건(순수 / 엠보 적용 / 반응성염료 적용 / 최종 피니시 적용) × 4개 크기

  | 크기 | 치수 | 면적 | 장당 가격 (USD 30/sqft 기준) |
  |------|------|------|------------------------------|
  | 샘플 | 30 × 30 cm | 0.97 sqft | $29.10 |
  | 정규원단 1 | 150 × 100 cm | 16.15 sqft | $484.50 |
  | 정규원단 2 | 100 × 100 cm | 10.76 sqft | $322.80 |
  | 정규원단 3 | 90 × 60 cm | 5.81 sqft | $174.30 |

- 장당 가격 = 면적(sqft, 소수 2자리) × 가공 조건별 sqft 단가. 특정 조합은 운영 도구의 가격표에서 개별 가격으로 고정할 수 있다.
- 최소 물량 20 sqft는 **정규원단 면적 합계** 기준이며, 샘플은 제외한다. 샘플만 주문하면 최소 물량 없이 주문당 최대 10장까지 받는다.
- 정규원단이 20 sqft 미만이면 결제 버튼이 비활성화되고, 100 sqft를 넘으면 PayPal 결제 대신 발주서 경로만 열린다.
- **C 경로가 필요한 이유:** PayPal Korea 정책상 한국 계정끼리는 결제를 주고받을 수 없다.

### 번호 체계

| 문서 | 형식 | 발행 위치 |
|------|------|----------|
| 개인 주문번호 | `MYC-YYMMDD-XXXX` | 결제 화면 (PayPal `invoice_id`에도 기록) |
| 발주희망서 번호 | `POR-YYMMDD-XXXX` | 발주희망서 화면 |
| 인보이스 번호 | `INV-YYMMDD-XXXX` | 내부 인보이스 작성기 |

## 2. A. 개인 주문 (PayPal 즉시 결제)

| 단계 | 담당 | 처리 기한 | 작업 |
|------|------|----------|------|
| A1 결제 | 고객 | — | 배송 정보 입력 → 주문 조건 동의 → PayPal 결제 |
| A2 결제 확인 | 재무 | 영업일 1일 | PayPal 알림 메일 확인 → 아래 **대조 체크리스트** 수행 |
| A3 주문 확인 메일 | 영업 | 영업일 1일 | 주문번호·발송 예정일 안내 |
| A4 출고 | 생산 | 리드타임 내 | 재단·검수·포장 → 상업 인보이스 2부 동봉 |
| A5 발송 처리 | 영업 | 출고 당일 | PayPal 거래에 운송장 번호 입력 (판매자 보호 요건) → 고객에게 운송장 안내 |

### 결제 대조 체크리스트 (A2, 필수)

현재 1단계는 결제 금액을 브라우저에서 만들기 때문에, 화면을 조작하면 금액을 바꿔 결제할 수 있다. **아래 대조가 끝나기 전에는 절대 출고하지 않는다.**

- [ ] PayPal 거래의 `Invoice ID` = 주문번호 `MYC-…`
- [ ] 품목별 `장수 × 장당 가격`이 현재 가격표와 일치 (PayPal 품목 SKU 예: `EM-01-r1` = EM-01 정규원단 1)
- [ ] `결제 총액 = 품목 합계 + 배송비`
- [ ] 정규원단 면적 합계 ≥ 20 sqft 또는 샘플만 10장 이하 (PayPal `custom_id` 예: `32.3sqft/0smp`)
- [ ] 배송 국가가 대한민국이 아님
- [ ] 결제 상태 `Completed` (`Pending`·`On hold`이면 대기)

### PayPal 인보이스 대체 경로

`VITE_PAYPAL_CLIENT_ID`가 설정되지 않은 동안에는 고객이 "주문 보내고 인보이스 요청"을 누른다. 이 경우 주문 메일을 받은 뒤 **B3의 PayPal 인보이스 발행 절차**를 따른다.

## 3. B. 발주 주문 (발주희망서 → 승인 인보이스 → 결제 → 발송)

| 단계 | 담당 | 처리 기한 | 작업 |
|------|------|----------|------|
| B1 발주희망서 접수 | 고객 | — | `/shop/po` 작성 → "발주희망서 발송" (메일) + 필요 시 PDF 첨부 |
| B2 검토·승인 | 영업 + 생산 | **영업일 2일** (고객에게 안내한 기한) | 재고·생산 일정 확인, 단가 결정(희망 단가 참고), 인코텀즈·결제 조건 확정, 신용 확인 |
| B3 승인 인보이스 발송 | 영업 | B2 당일 | ① PayPal에서 인보이스 발행 → ② 내부 작성기로 Proforma 작성 → ③ 승인 메일 발송 |
| B4 결제 확인 | 재무 | 입금 당일 | PayPal 결제 완료 알림 또는 T/T 입금 확인. 금액·인보이스 번호 대조 |
| B5 생산·출고 | 생산 | 인보이스에 적은 리드타임 | 배치 원산지 기록, 검수, 포장 |
| B6 선적 서류 | 영업 | 출고 당일 | Commercial Invoice + 포장명세서 + (필요 시) 원산지증명서 발행. 운송장 안내 |

### B3 상세: 승인 인보이스 만들기

1. **내부 작성기 열기:** `npm run admin` 실행 후 `http://localhost:8080/admin/invoice` (운영 도구 실행 중이면 상단의 "인보이스 작성기" 링크)
   - 공개 사이트에는 이 페이지가 없다. 관리자 빌드에만 포함된다.
2. **발주 내용 불러오기:** 받은 발주희망서 메일 본문을 "붙여넣기 → 자동 채우기"에 넣고 **Import**를 누른다. 회사·담당자·품목·수량·조건이 자동으로 채워진다.
3. **조건 확정:** 단가, 할인, 배송비, 인코텀즈, 결제 조건, 유효기간(기본 14일), 예상 선적일을 확정한다. 국내 거래는 VAT 10%를 입력한다.
4. **결제 수단별 처리:**
   - **PayPal 인보이스:** PayPal 대시보드 → 인보이스 발행. 품목명 `SKU 품명 크기`, 수량(장), 장당 단가는 USD로 입력하고, 메모에 `INV-…`와 `POR-…` 번호를 적는다. 발행한 인보이스 링크를 작성기의 "PayPal invoice link" 칸에 붙여 넣는다.
   - **T/T 송금:** 계좌 정보가 인보이스에 자동으로 인쇄된다(`src/content/bankAccounts.ts`).
   - **원화 계좌이체(국내):** 세금계산서를 별도로 발행한다.
5. **PDF 저장:** "Print / save PDF"로 저장한다. 파일명은 `INV-…_회사명.pdf`.
6. **승인 메일 발송:** "Approval email draft"를 누르면 메일이 작성된다. PDF를 첨부해 보낸다.

### 결제 조건 운영 기준

| 코드 | 조건 | 적용 기준 |
|------|------|----------|
| ADV100 | 100% 선결제 | 기본값, 신규 거래처 |
| ADV50 | 50% 선금 / 50% 선적 전 | 정규원단 1,000 sqft 이상 또는 맞춤 개발 (내부 승인) |
| NET30 | 30일 후불 | 거래 이력이 있는 승인 거래처만 (재무 승인 필수) |

## 4. C. 국내 주문

1. **견적서 발행:** 작성기에서 결제 수단 `Domestic bank transfer (KRW)`, VAT 10%로 견적서를 만든다.
2. **환산 기준:** USD 가격을 원화로 바꿀 환율 기준(예: 견적일 기준 하나은행 매매기준율)을 견적서 메모에 적는다.
3. **세금계산서:** 입금 확인 후 사업자등록번호로 전자세금계산서를 발행한다.
4. **출고:** 출고 절차는 B5와 같다.

## 5. PayPal 설정 절차 (최초 1회)

| 순서 | 작업 | 비고 |
|------|------|------|
| 1 | PayPal **비즈니스 계정**(한국) 개설·인증 | 법인 서류 필요 |
| 2 | 출금용 국내 은행 계좌 연결 | 원화 출금. 15만 원 미만 출금은 수수료가 있다(공식 수수료표 확인) |
| 3 | developer.paypal.com → **Sandbox 앱** 생성 → 테스트 계정으로 결제 시험 | `.env`의 `VITE_PAYPAL_CLIENT_ID`에 Sandbox Client ID 입력 |
| 4 | **Live 앱** 생성 → Live Client ID를 Lovable 환경변수 `VITE_PAYPAL_CLIENT_ID`에 등록 | Client ID만 넣는다. **Secret은 절대 프런트엔드에 넣지 않는다** |
| 5 | 판매자 알림 메일 켜기 (결제 수신, 분쟁, 인보이스 결제) | 영업·재무 공용 메일 |
| 6 | 수수료·환전 조건 확인 | 해외 결제 수수료와 환전 스프레드는 [PayPal Korea 판매자 수수료](https://www.paypal.com/kr/webapps/mpp/merchant-fees)에서 최신값 확인 → 원가 모델(002)에 반영 |

## 6. 세무·통관 점검 항목 (세무사·관세사 확인 필요)

| 항목 | 내용 |
|------|------|
| 부가가치세 | 해외로 수출하는 재화는 일반적으로 **영세율** 대상이다. 수출 증빙(수출신고필증 또는 특송·우편 발송 증빙, PayPal·외화 입금 내역)을 보관한다. 국내 거래는 VAT 10%와 세금계산서. |
| 수출 신고 | 특송·우편으로 소량 발송할 때의 수출 신고 방식(간이·일반)은 특송사·관세사와 확인한다. |
| HS 코드 | 순수 균사 매트의 품목 분류는 **관세사 확인 후** 운영 도구 → 크기·가격 → 판매자 정보의 `hsCode`에 입력한다. 국가별 관세율과 DDP 조건 가격 산정에 필요하다. |
| 외화 수취 | PayPal·T/T 외화 입금 내역을 인보이스 번호와 짝지어 장부에 기록한다. |
| 원산지 | 인보이스에 "Republic of Korea"가 인쇄된다. FTA 특혜관세가 필요한 바이어에게는 원산지증명서를 발급한다. |

## 7. 분쟁·환불

- **고지 사항:** 천연 배양 소재 특성상 배치 간 색상·질감 차이가 있다는 점을 결제 화면과 인보이스에 고지하고 있다. 이 차이는 하자가 아니다.
- **분쟁 대응:** PayPal 분쟁이 접수되면 영업일 3일 안에 운송장·검수 사진·인보이스로 대응한다.
- **판매자 보호 요건:** 운송장 번호를 PayPal 거래에 입력해 두는 것이 판매자 보호의 전제 조건이다(A5).

## 8. 2단계 자동화 계획 (권장)

| 항목 | 현재 (1단계) | 2단계 |
|------|-------------|-------|
| PayPal 주문 생성 | 브라우저에서 생성 (금액 수동 대조) | **서버 함수**(예: Supabase Edge Function)가 가격표로 금액을 계산해 Orders v2 주문을 생성·확정. PayPal 공식 권장 방식 |
| 결제 확인 | 알림 메일 + 수동 대조 | 웹훅 `PAYMENT.CAPTURE.COMPLETED`로 주문 DB 자동 기록 |
| 승인 인보이스 | PayPal 대시보드 수동 발행 + 작성기 PDF | PayPal Invoicing API v2로 발행·발송 자동화, `INVOICING.INVOICE.PAID` 웹훅으로 결제 완료 반영 |
| 발주희망서 접수 | 메일 | 접수 DB + 담당자 알림, 상태 관리(접수 → 승인 → 결제 → 출고) |
| 국내 결제 | 계좌이체 수동 확인 | 토스페이먼츠 등 국내 PG의 가상계좌·카드 결제 |

2단계 전환 시 `src/shop/paypal.ts`의 `buildOrder`를 서버로 옮기고, 결제 화면의 `createOrder`·`onApprove`가 서버 엔드포인트를 호출하도록 바꾸면 된다.
