# 로또 6/45 기대값 최적화 번호 생성기 (개인용)

매주 구매용 조합 20개를 만들고, 별도로 보관용 조합 1,000개를 저장소에 보관했다가
토요일 추첨 뒤 두 묶음을 모두 당첨번호와 대조해 결과를 기록하는 도구입니다.
파이썬 표준 라이브러리만 사용하므로 별도 설치 패키지가 없습니다.

## 1. 정직한 전제

- 어떤 조합이든 당첨 확률은 정확히 같습니다. 1등은 1/8,145,060 입니다. 이 프로그램도 그 확률은 바꾸지 못합니다.
- 1~3등 당첨금은 당첨자끼리 나눕니다. 남들이 덜 고르는 조합은 당첨됐을 때 받는 금액이 커집니다.
- 동행복권 공개 데이터(회차별 등수별 당첨자 수)로 수동 구매자의 번호 선호도를 추정해, 선호도가 낮은 조합을 고릅니다.
- 그 결과 게임당 세후 기대값은 약 417원에서 약 460원으로 오르지만 여전히 1,000원보다 낮습니다. 장기적으로는 돈을 잃는 구조입니다.

## 2. 설치와 실행 (Windows)

1. Python 3.8 이상을 설치합니다. https://www.python.org/downloads/ 설치 화면에서 "Add python.exe to PATH" 를 체크합니다.
2. `lotto.bat` 을 더블클릭하면 메뉴가 뜹니다.
3. 처음 한 번은 `[1] 데이터 갱신` 으로 전 회차 데이터를 받습니다. 동행복권 서버가 간헐적으로 연결을 끊으므로 수 분이 걸릴 수 있고, 중단돼도 다시 실행하면 받은 곳부터 이어받습니다.
4. `[2] 구매 조합 20개` 를 누르면 `out/picks_<회차>.csv` 에 저장됩니다.
5. 토요일 추첨 뒤 `[4] 결과 대조` 에 회차 번호를 넣으면 20개와 보관용 1,000개를 함께 채점하고 `out/ledger.csv` 장부에 누적합니다.

메뉴 없이 바로 실행하려면 인수를 붙입니다.

```
lotto.bat weekly
lotto.bat check --round 1247
lotto.bat generate -n 20 --round 1248
```

Mac/Linux 에서는 `python3 lotto_ev.py <명령>` 으로 같은 기능을 씁니다.

## 3. 명령 요약

| 명령 | 역할 | 산출물 |
|---|---|---|
| `update` | 동행복권 API 에서 전 회차 데이터 내려받기, 증분 갱신 | `data/history.json` |
| `verify` | 추첨 균등성 카이제곱 검정, 회차 간 독립성, 빈출번호 전략 백테스트 | 화면 |
| `calibrate` | 번호 선호도 모델 적합, 최근 52회차로 검증 | `data/model.json` |
| `generate -n 20` | 다음 회차 구매용 조합 | `out/picks_<회차>.csv` |
| `vault -n 1000` | 다음 회차 보관용 조합 | `vault/vault_<회차>.csv` |
| `check --round R` | 추첨 결과 대조, 장부 기록 | `out/ledger.csv` |
| `weekly` | 갱신, 직전 회차 대조, 모델 재보정, 다음 회차 20개와 1,000개 생성, 보고서 | `reports/weekly_<회차>.md` |
| `backtest --rounds 52` | 과거 회차에 같은 방식을 적용한 모의 성적 | 화면 |

## 4. 모델이 하는 일

1. 매 회차 판매 게임 수를 알면 균등 선택 가정에서 등수별 당첨자 수의 기대치가 정확히 계산됩니다.
2. 실제 당첨자 수를 그 기대치로 나눈 비율이 1보다 크면 그 번호 조합을 사람들이 많이 골랐다는 뜻입니다.
3. 3등, 4등, 5등 비율을 추첨된 번호와 구조 특징(연속쌍, 직전 회차 번호 포함)에 회귀해 번호별 선호도를 추정합니다. 등수마다 추첨번호 포함 개수가 다른 점은 1차 근사 스케일로 보정합니다.
4. 임의 조합의 선호도를 계산해 전체 평균이 1이 되도록 정규화하고, 자동 구매 비중 하한(기본 0.6)보다 낮게는 내려가지 않게 합니다.
5. 선호도 하위 5% 조합 가운데 서로 겹치는 번호가 2개 이하가 되도록 20개를 고릅니다. 보관용 1,000개는 하위 10% 가운데 겹침 3개 이하로 고릅니다.
6. 조합별로 "당첨 시 1등 예상 당첨금"과 "게임당 기대값"을 포아송 분할 모형으로 계산해 함께 출력합니다. 세금은 200만원 초과 시 3억 이하 22%, 3억 초과분 33% 를 적용합니다.

검증 결과(적합에 쓰지 않은 최근 52회차)에서 사전 예측 선호도와 실제 당첨자 비율의 상관계수는 5등 +0.79, 3등 +0.59, 1등 +0.35 였습니다. 모델은 당첨자가 많이 나올 조합과 적게 나올 조합을 사전에 구분합니다. 다만 당첨 횟수 자체는 무작위 선택과 같습니다.

## 5. 주간 자동 실행

- 클라우드 예약 작업이 매주 일요일 아침(한국 시간)에 `weekly` 를 실행해 직전 회차를 대조하고 다음 회차 조합을 생성한 뒤 `lotto-ev` 브랜치에 커밋합니다. 결과는 `reports/weekly_<회차>.md` 와 세션 메시지로 전달됩니다.
- 로컬 PC 에서 자동화하려면 Windows 작업 스케줄러에 `lotto.bat weekly` 를 매주 일요일에 등록하면 됩니다.

## 6. 폴더 구성

```
tools/lotto-ev/
  lotto_ev.py        프로그램 본체 (표준 라이브러리만 사용)
  lotto.bat          Windows 메뉴 실행 파일
  data/history.json  회차별 당첨번호, 판매액, 등수별 당첨자 수와 당첨금
  data/model.json    번호 선호도 모델
  out/picks_<회차>.csv   구매용 20개
  vault/vault_<회차>.csv 보관용 1,000개
  out/ledger.csv     누적 장부 (구매 20개와 보관 1,000개를 구분)
  reports/           주간 보고서
```

## 7. 유의점

- 보관용 1,000개의 당첨금은 실제 1~3등 1인당 당첨금을 그대로 적용합니다. 실제로 그 조합을 샀다면 분할 인원이 늘어 금액이 달라집니다.
- 자동 구매 비중 하한 0.6 은 가정값입니다. `--floor` 옵션으로 바꿀 수 있고, 값이 낮을수록 기대값 추정이 낙관적으로 나옵니다.
- 동행복권 사이트 개편으로 API 주소가 바뀌면 `API_PAGE`, `API_LATEST` 상수를 고쳐야 합니다.
- 온라인 구매는 회차당 5,000원, 판매점은 1회 10만원 한도가 있습니다. 판매 목적의 사용이나 대리구매는 복권 및 복권기금법 위반입니다.
